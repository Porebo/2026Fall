SAMPLE QUALITY EVALUATION
Input quality of the 30 sampled wellbore diagrams, and why none is excluded
Version 1.0, November 11, 2026

Companion to sampling-plan.txt (version 1.2). Measurements are in
pdf-quality-profile.csv, produced by ../../scripts/profile_pdf_quality.py.


1. PURPOSE
==========

The study gives each diagram, as a PDF file, to an AI and asks whether the
diagram contains the data required by 14 CCR section 1726.4.1. What the AI can
read depends on the file: whether it carries a text layer, the resolution of
any scanned image, the size of the printed text, the size and orientation of
the page. A diagram can contain a required item that the AI cannot read.

This document records the input quality of the 30 sampled files, states the
decision that no file is excluded, deleted, replaced, or altered on grounds of
quality, gives the reasons for that decision, and sets out how quality is
handled in the analysis instead.


2. WHAT WAS EVALUATED
=====================

The 30 files in diagrams/ (W01 to W30), exactly as downloaded from WellSTAR on
November 11, 2026. Each file's SHA-256 checksum is recorded in
screening-log.csv. The evaluation read the files only; no file was opened in
an editor, converted, OCR-processed, rotated, cropped, or re-saved.


3. MEASURES
===========

Measured from each file by ../../scripts/profile_pdf_quality.py:

  Pages                     number of pages
  FileKB                    file size
  PageWidthIn, PageHeightIn size of the first page, in inches
  Orientation               Landscape when the page is wider than tall
  TextChars, Words          characters and words in the PDF's text layer
                            (text that can be extracted without OCR)
  RasterImages              number of embedded images
  LargestImagePageCoverage  share of the first page's area covered by the
                            largest embedded image
  LargestImageDPI           resolution of that image: its pixel width divided
                            by its printed width in inches
  MinFontPt, MedianFontPt   smallest and median size of text in the text layer
  InputType                 classification, by this rule:
                              Scanned  fewer than 50 characters of text
                              Mixed    50 to 999 characters of text, and the
                                       largest image covers at least 25% of
                                       the page
                              Native   all others

Recorded by looking at the pages (column VisualNotes): content printed
sideways, multi-borehole layouts, and template labels that conflict with the
operator's own marking.

5. DECISION
===========

No diagram is excluded, deleted, replaced, or modified because of the quality
of its file. All 30 remain in the sample exactly as downloaded.


6. REASONS
==========

6.1 Excluding a file after it was randomly selected would end the random
    sample.
    The sample is a simple random sample of eligible wells, drawn by screening
    a random ordering of the frame against eligibility rules fixed before any
    well was screened (sampling-plan.txt, sections 2 and 5). File quality is
    not an eligibility rule, apart from legibility to a person (rule 5(d)),
    which all 30 meet. Removing a file now, for a reason not in those rules,
    would make the sample a set chosen by the researcher, and results could
    no longer be generalized to diagrams on file in WellSTAR.

6.2 Exclusion would bias the results in the AI's favor.
    File quality plausibly affects how well an AI reads a diagram. Dropping
    the hardest files would leave the files the AI is most likely to read
    correctly, and the study would overstate how well the method works. The
    pilot exists to find where the method fails as well as where it succeeds.

6.3 The files are what the worker actually receives.
    The scenario is a worker retrieving the diagram already on file and
    checking it before reuse (../design/scenario-business-need.txt,
    section 2). The worker cannot choose a better-scanned copy; the file in
    WellSTAR is the record. A method that works only on clean files does not
    solve the worker's problem.

6.4 File quality is a dimension of data quality to be measured, not noise
    to be removed.
    Wang and Strong (1996, p. 6) state that "Representational DQ and
    accessibility DQ emphasize the importance of the role of systems" and
    that "high-quality data should be intrinsically good, contextually
    appropriate for the task, clearly represented, and accessible to the data
    consumer." A low-resolution scan or text printed at 3 point is a
    representational and accessibility property of the record. In an
    information quality study it is part of what is being examined.
    (PDF with the passage highlighted:
    ../../04-literature/papers/Wang, 1996, Beyond Accuracy - What Data Quality Means
    to Data Consumers, Journal of Management Information Systems.pdf)

6.5 The poorer files are a real share of what is on file.
    Six of the 30 (20%) are scanned or mixed. Because the sample is random,
    that proportion is an estimate of the share among diagrams on file.
    Removing them would hide a condition that a real deployment would meet,
    and would leave no cases with which to study it.

6.6 Removing files would reduce the sample below its justified size.
    n = 30 rests on the pilot-study rule of thumb of 30 or more to estimate a
    parameter (Lancaster, Dodd, & Williamson, 2004, p. 308; sampling-plan.txt,
    section 3). Dropping six files would leave 24.

6.7 Replacing a file would select on the outcome.
    The plan allows a replacement only for a well that fails an eligibility
    rule, taken strictly in order. Replacing a legible but poor-quality file
    with the next well in the queue would mean choosing wells by how easy their
    files are to read, which the plan does not permit.

6.8 Unaltered files keep the inputs verifiable.
    Every file matches the checksum recorded at download. Anyone repeating
    the study can download the same documents from WellSTAR, confirm they are
    identical, and give an AI exactly the inputs this study used. A cleaned or
    converted file could not be checked this way.


7. HOW QUALITY IS HANDLED INSTEAD
=================================

7.1 Inputs as served. In the primary condition each AI receives the original
    file from diagrams/, with no OCR, rotation, cropping, splitting, or
    conversion.

7.2 Reference answers distinguish missing from unreadable. When preparing the
    reference (ground-truth) answers, the human grader records each required
    item as Present, Absent, or Illegible (present on the page but not
    readable by a person). This separates errors caused by the file from
    errors of judgment.

7.3 How each AI read the file is recorded. AI tools read PDFs differently:
    some use only the text layer, some render page images, some use both.
    For every run, the tool, model version, date, and reading method (where
    the tool discloses it) are recorded. A tool that reads only the text layer
    has no text to read in W06, W11, and W25, and this is reported, not
    hidden.

7.4 Results are reported by input type. Agreement between the AI and the
    reference answers is reported for all 30 diagrams and separately for
    Native, Mixed, and Scanned files, and errors are examined against the
    measures in Section 3 (smallest text, image resolution, page size,
    orientation).

7.5 Any cleaned copies are a separate condition. If a later condition tests
    the effect of preprocessing (for example OCR or rotation), the processed
    copies are stored in a separate folder with their own checksums. They
    never replace the originals.


8. LIMITATIONS
==============

- The Native, Mixed, and Scanned thresholds are this study's own and are
  stated in Section 3 so they can be applied the same way again.
- Image resolution describes embedded raster images only; vector drawings
  have no resolution in this sense.
- AI tools reduce page images to an internal resolution that they do not
  always disclose, so the resolution the AI actually sees may be lower than
  the file's.
- With three Scanned and three Mixed files, comparisons between input types
  in this pilot are descriptive, not tests of significance.
