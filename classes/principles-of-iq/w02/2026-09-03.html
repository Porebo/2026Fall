Session Focus

From Information Value to Data Practice

This session completed the lecture on information value by connecting data categories and data requirements to practical data work. The class then moved into the first dataset-analysis assignment and a demonstration of OpenRefine.

  • Data categories help people communicate precisely about data and understand how it can be used.
  • Data analysis can reveal unusual values, blanks, inconsistent labels, and other anomalies.
  • An anomaly is not automatically a data quality error: quality can be determined only when the relevant data requirements are known.

Core Concept

Data Categories by Structure

Structured data
Data with a formal, predictable syntax that systems can read directly. Examples include relational databases, comma-separated value (CSV) files, XML, and JSON.
Unstructured data
Human-readable content that traditionally required preprocessing before conventional systems could use it. Examples include narrative documents, reports, and free-form text.
Semi-structured data
Data containing both organized fields and free-form content. Email is a familiar example: sender, recipient, date, and subject are structured, while the message is free-form.

The categories are better understood as a continuum than as completely separate boxes. A relational table may be highly structured while still containing semi-structured comments or address fields.

Emerging Topics

AI and the Structure Transition

Large language models can read and interpret documents, images, and audio, so much more human-readable data is now machine-readable in a practical sense. The main enterprise use today is often to transform unstructured or semi-structured material into structured records that legacy systems can process.

  • Legacy systems such as billing, payroll, CRM, ERP, and master data management systems still expect structured inputs.
  • AI extraction can parse documents and free-form fields into fields such as names, addresses, dates, and entities.
  • Semantic computing aims toward systems that can accept ordinary documents, interpret them, and carry out processing directly.
  • Embedding text as numeric vectors may make semantic content faster to search and process.
  • AI remains slower and less deterministic than traditional rule-based systems, especially at very large scale.

Framework

Operational Data Categories

Operational data supports the day-to-day work of an organization. Four important categories are:

  • Master data describes the nouns of the organization’s data vocabulary: people, places, and things such as customers, patients, products, employees, vehicles, and buildings.
  • Transactional data describes events or actions, like sales orders, credit-card payments, and insurance claims. It acts like the verbs or sentences connecting master-data entities.
  • Reference data provides agreed-upon codes and classification schemes, such as state, country, currency, postal, building, or job codes.
  • Metadata is data about data. It labels, describes, and characterizes data so people and systems can retrieve, interpret, and use it correctly.

Data can also be classified by origin or function, including user-generated data and machine-generated sensor data. Sensor readings can support predictive maintenance by identifying conditions that may precede equipment failure.

Data Management

Master, Transactional, and Reference Data

Master data and semantic encoding

Master data represents real-world entities and assigns each one a stable identifier within its context. A customer number, patient number, vehicle identification number, or employee number lets systems distinguish one entity from another even when names or addresses change or are represented differently.

Semantic encoding means assigning an identifier as a stand-in for the entity and consistently reusing that identifier. This makes deduplication, integration, and aggregation possible. Master data aims for one master record per entity, while transactional data intentionally contains many records for repeated events.

Reference data and interoperability

Reference data standardizes codes so separate systems can interpret values consistently. Codes may be external standards, such as ISO country or currency codes, or internal organizational codes, such as campus building codes. Consistent reference codes improve integration and interoperability without requiring every code to receive a new universal identifier.

Data Governance

Metadata, Catalogs, and Glossaries

A raw value can be ambiguous without context. A date such as 07/04/1959 has a format, but metadata is needed to say whether it is a birth date, transaction date, or some other business date.

  • Technical metadata describes systems, structures, data types, quality rules, and standards.
  • Business metadata describes operational meaning and rules, such as how net pay is calculated or when a product can be returned.
  • Data catalogs describe what data an organization has, where it is located, and its characteristics.
  • Business glossaries explain business terms and derived values, including the logic used to calculate them.

Data littering is distributing data without enough metadata for others to understand or use it. A file that made sense to its original creators can become nearly useless when its purpose, definitions, timing, and rules are lost.

Quality Requirements

Data Quality Depends on Requirements

Data requirements include data models, schemas, business rules, standards, and other specifications. The course definition is:

Data quality is the conformance of data to data requirements.

Therefore, missing or poorly defined requirements lead to poor data quality assessment. Finding a blank value, an unusual label, or an inconsistent format is data exploration; deciding that it is a quality defect requires knowing what the data is supposed to contain.

Models are useful but never complete. As George Box’s well-known observation puts it, “All models are wrong, but some are useful.” Data lakes preserve raw data so it can be revisited when a model changes or a transformation turns out to be wrong.

Tool Demonstration

Exploring Data with OpenRefine

OpenRefine is an open-source tool for exploring and transforming data. It is similar to a spreadsheet but includes features for profiling and working with messy datasets.

  1. Install OpenRefine and create a project by uploading the assigned data file.
  2. Review the project summary: file format, row count, columns, and sample records.
  3. Use the dropdown menu on a column and choose a facet, such as a text facet.
  4. Inspect value counts to find blanks, unusual values, capitalization differences, spelling variations, and other anomalies.
  5. Describe what you observe without claiming a data quality error unless the requirements support that conclusion.

The demonstration used a dataset with 860 rows and showed how facets can reveal inconsistent values such as variations in labels for movies and television shows, as well as blank country values.

Emerging Topics

Agentic AI and Process Automation

Agentic AI extends a prompt-and-response model by allowing a language model to use connected systems, make intermediate decisions, and carry out tasks such as querying a database, writing an email, creating a Jira ticket, or booking travel.

  • Agents can act like software workers that loop through decisions and actions.
  • Probabilistic models can hallucinate or make incorrect predictions, so guardrails and human oversight are important.
  • Latency remains a challenge: traditional deterministic systems often operate in milliseconds or microseconds, while AI reasoning may take seconds or longer.
