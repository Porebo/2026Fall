1Executive Finding

Executive finding: orglev4_name is a curated reporting classification, not necessarily a raw organizational attribute. Its value is produced by ordered CASE expressions, stored in downstream materialized views, and exposed by the summary table. Some outputs come from source data; others are injected as hard-coded reporting labels.

2What This Investigation Needed to Establish

The investigation addressed two related questions:

  1. Definitions: What does each output name mean, and is it inherited from source data or assigned by business logic?
  2. Lineage: Where, exactly, is the value transformed before it reaches the summary table?

The summary table does not explain its own derivation. It receives an already manufactured value from upstream objects.

4The Two Transformation Layers

Layer 1: bi.fv_wellcomp_v

This view reads the materialized well-completion data and joins:

  • ds_usoxyp.mast_organization_unit as m, using org_seqno.
  • ds_ekpspp.dss_wn_team as wn, using reservoir_cd and cost_center.

It then creates a normalized orglev4_name with its own CASE expression.

Layer 2: bi_surv.dv_surv_ws_org_units

This view reads crc.mv_bi_wellcomp_v and applies the surveillance-specific classification. This is the controlling transformation for the value that reaches the surveillance well dictionary and summary chain.

Important distinction: the database does not mutate the original source rows. It transforms source attributes into a reporting value, then materialized views store that result. The resulting value is therefore modeled reporting data, not necessarily the original organizational value.

5Confirmed Final CASE Logic

CASE
    WHEN UPPER(wc.reg_name) = 'ELK HILLS'
        THEN COALESCE(
            UPPER(wn.kpi_group),
            UPPER(wc.orglev4_name)
        )

    WHEN wc.org_seqno = 1901030000
        THEN 'PICO'

    WHEN wc.org_seqno = 1901000000
        THEN 'LONG BEACH UNIT'

    WHEN UPPER(wc.orglev4_name) IN (
        'NPR2E', 'NPR2W', 'SPRB', 'NPR1', 'SPRA'
    )
    OR UPPER(wc.at_name) = 'TIDELANDS'
        THEN 'TIDELANDS'

    WHEN UPPER(wc.orglev4_name) = 'GENERAL'
        THEN CASE
            WHEN UPPER(wc.subat_name) = 'GENERAL'
                THEN CASE
                    WHEN UPPER(wc.at_name) = 'GENERAL'
                        THEN UPPER(wc.reg_name)
                    ELSE UPPER(wc.at_name)
                END
            ELSE UPPER(wc.subat_name)
        END

    ELSE COALESCE(
        UPPER(wc.orglev4_name),
        UPPER(wc.subat_name),
        UPPER(wc.at_name),
        UPPER(wc.reg_name)
    )
END AS orglev4_name

7The GENERAL Branch

When the source level-four value is GENERAL, the logic tries to replace that generic name with a more specific hierarchy value:

Source state Returned value
orglev4_name = 'GENERAL' and subat_name <> 'GENERAL' UPPER(wc.subat_name)
orglev4_name = 'GENERAL', subat_name = 'GENERAL', and at_name <> 'GENERAL' UPPER(wc.at_name)
The three levels are GENERAL UPPER(wc.reg_name)
Null behavior: the nested GENERAL branch does not use COALESCE. A null subat_name or at_name can therefore produce a null result instead of continuing to another available hierarchy level.

9Where to Examine the Closest Raw Organizational Data

To inspect the organizational value before the downstream surveillance classification, start with:

ds_usoxyp.mast_organization_unit

Join it to the well-completion data by org_seqno:

SELECT
    wc.api_no14,
    wc.org_seqno,
    m.reg_name,
    m.at_name,
    m.subat_name,
    m.orglev4_name AS source_orglev4_name,
    m.orglev5_name
FROM crc.mv_bi_wellcomp wc
LEFT JOIN ds_usoxyp.mast_organization_unit m
    ON wc.org_seqno = m.org_seqno;

This is the best starting point for comparing the source organizational name with the painted reporting output.

For deeper well-completion lineage, do not treat bi.dv_wc_wellcomp_union as a single raw source. It is an integration view with three branches:

Union branch Upstream object Role
CRC bi.dv_wc_crc_wellcomp Uses ds_usoxyp.mast_zone, ds_usoxyp.mast_well, and related reference objects.
Wilmington / Ingres ingres_dev.fv_wilmington_completions Forwards from ingres_dev.fv_completions and applies source-specific classifications.
Other / manual legacy_integrations.tbmanual_well_entry Manual well records with their own supplied attributes.

The union itself also injects values. For example, Ingres asset_name values are mapped to fixed org_seqno values for LONG BEACH UNIT, PICO, and TIDELANDS. It also translates status, well type, redrill, and operating-method codes.

Query-ready branch objects

Query these three objects separately to inspect the inputs before they are combined by bi.dv_wc_wellcomp_union:

Branch Object to query Starter query
CRC bi.dv_wc_crc_wellcomp SELECT * FROM bi.dv_wc_crc_wellcomp LIMIT 100;
Wilmington / Ingres ingres_dev.fv_wilmington_completions SELECT * FROM ingres_dev.fv_wilmington_completions LIMIT 100;

To inspect the standardized combined result, query:

SELECT *
FROM bi.dv_wc_wellcomp_union
LIMIT 100;
Set-operation detail: the database definition uses UNION, not UNION ALL. The three branch queries provide compatible, positionally aligned column lists, and the UNION removes rows that are exact duplicates across the combined output. The inputs are not all physical tables: the CRC and Wilmington/Ingres branches are views, while the manual/legacy branch is a table.
Important discovery: the three upstream objects do not have the same native schema. The CRC branch returned 49 columns, the Wilmington/Ingres branch returned 36 columns, and the manual/legacy table returned 17 columns. The union makes them compatible by explicitly selecting columns in a common order, renaming source fields, converting source codes, and supplying typed NULL values where a branch has no equivalent field. Therefore, the shared schema is manufactured by the union query; it is not inherited unchanged from the three sources.

Examples of this standardization include:

  • The Wilmington/Ingres branch converts values such as Oil and Inj into standardized completion types such as PROD_OIL and INJ_H2O.
  • The Wilmington/Ingres branch converts asset names such as PICO, LONG BEACH UNIT, and TIDELANDS into fixed organization sequence values.
  • The manual/legacy branch supplies a smaller set of fields, while the union supplies NULL for fields that do not exist in that source.

The deeper lineage is therefore:

CRC / Ingres / manual sources → bi.dv_wc_wellcomp_union → bi.fv_wellcomp → crc.mv_bi_wellcomp
Correction to the earlier endpoint: bi.dv_wc_wellcomp_union is not the highest/root object. There is no single root table for the entire population because the view combines multiple source systems. For the closest organizational source specifically, ds_usoxyp.mast_organization_unit remains the key object joined by org_seqno in bi.fv_wellcomp_v.

ds_ekpspp.dss_wn_team should be examined separately as a reporting lookup because it can provide a KPI group that replaces the source organizational name for Elk Hills.

11Conclusion

orglev4_name is a curated reporting value. Some output names are inherent in source organizational data; others are injected by hard-coded business rules so that records fit a desired reporting schema. The summary table stores the final painted result but contains no indication that the value was manufactured upstream.

The most defensible interpretation is:

Source attributes
    + lookup mappings
    + ordered business rules
    = derived reporting classification
